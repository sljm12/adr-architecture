# Data Model and Interaction State

## Existing Group

The feature edits an existing SystemGroup within the current DiagramDocument.

| Field | Type | Rules |
|---|---|---|
| id | UUID | Stable group identity; never regenerated by membership addition |
| diagramId | UUID | Must match the active diagram |
| name | string | Existing non-blank, per-diagram unique group name |
| memberComponentIds | UUID[] | At least two unique IDs; every member is an eligible Software System in the same diagram; a component belongs to at most one group |
| position | { x, y } | Fitted boundary position in absolute domain coordinates |
| size | { width, height } | Positive fitted boundary dimensions including existing header and padding |
| createdAt | timestamp | Preserved when membership changes |
| updatedAt | timestamp | Updated when membership or fitted layout changes |

## Existing Component

The selected component is not recreated or copied.

| Field or reference | Rule during addition |
|---|---|
| id | Existing stable UUID is appended once to memberComponentIds |
| diagramId | Must match the selected group and active document |
| type | Must be software-system; Person, legacy/unclassified, group, missing, or cross-diagram items are rejected |
| position | Existing absolute position is preserved |
| name, description, timestamps | No component field is changed by this feature |
| relationships | Existing relationship IDs and component endpoints remain unchanged |
| ADR links | Existing component links remain attached to the same component ID |

## Group Membership

Membership is represented in the domain document by the group’s memberComponentIds and persisted
in the existing system_group_members table. The association is valid only when:

1. The group and component both exist in the active document.
2. The component is an eligible Software System.
3. The component is not already in the target group.
4. The component is not a member of any other group.
5. The resulting group has unique member IDs and a boundary enclosing every member with the
   established padding.

An invalid attempt is a no-op: the document, fitted boundary, undo/redo history, and persisted
document remain unchanged. A valid attempt appends one ID, fits the group boundary, and is one
undoable document revision.

## Transient Add Selection

Transient selection is frontend interaction state and is never persisted or included in undo
history until the author confirms the add.

| State | Fields | Meaning |
|---|---|---|
| none | none | No group-member candidate is pending |
| group-selected | groupId | An existing group is selected in ordinary canvas mode |
| group-member-candidate | groupId, componentId | The author selected the group, then Shift-selected a component for review |
| succeeded | groupId, componentId | The membership is committed; show success feedback and keep the group selected |
| rejected | groupId, componentId, reason | Duplicate, conflicting, missing, or ineligible candidate; document remains unchanged |

The existing multi-component selection used by the new-group form remains separate from these
states.

## State Transitions

| From | Event | To | Document mutation |
|---|---|---|---|
| none | Plain-click existing group | group-selected | None |
| group-selected | Shift-click existing component | group-member-candidate | None |
| group-member-candidate | Cancel, pane click, or new plain selection | none or ordinary selection | None |
| group-member-candidate | Candidate fails validation | rejected | None |
| group-member-candidate | Confirm valid addition | succeeded / group-selected | Append ID, refit group, push one history entry |
| succeeded | Save and reopen | group-selected | Persisted membership and layout are restored |
| succeeded | Undo | prior group-selected document | Remove the membership and restore prior group layout |
| prior state | Redo | succeeded | Reapply the same stable membership and fitted layout |

## Persistence Mapping

No new storage structure is needed:

- SystemGroup.id, name, layout, and timestamps map to system_groups.
- Each memberComponentIds entry maps to system_group_members(group_id, component_id).
- The current complete-document replacement remains the atomic persistence boundary.
- The existing primary key prevents duplicate rows; domain validation prevents duplicate IDs,
  cross-group membership, ineligible members, and invalid boundaries before persistence.
- Invalid complete-document replacements return HTTP 422 and do not replace the stored document;
  the client can retry the unchanged draft after a save failure.
